# Повышение безопасности системы

Для схемы `BionicPRO_C4_model.drawio.xml` добавлена SSO-архитектура через API Gateway и сервис управления учётными данными.

## Что добавлено:

* API Gateway как единая точка входа для клиентских приложений: приложения больше не ходят напрямую в разные backend-сервисы и IdP, 
* а проходят через общий слой доступа.
* Сервис управления учётными данными / Identity Broker, фактически роль Keycloak: он отвечает за федерацию внешних IdP, 
* проверку пользователей и выпуск внутренних сессий/токенов.
* Session/Token Store для хранения серверной сессии и связки с внешними access/refresh-токенами. Это нужно, 
* чтобы не передавать frontend токены, полученные от внешнего IdP.
* Внешние удостоверяющие службы страны присутствия: через них поддерживается аутентификация пользователей в разных странах.
* Региональный источник учётных записей: внешний источник данных об аккаунтах в стране представительства компании.

## Связи от приложений к API Gateway 

* Приложение настройки протеза, интернет-магазин и CRM используют единый механизм входа.
* API Gateway проверяет пользовательскую сессию, инициирует вход и получает внутренний контекст пользователя.
* Обозначена федеративная модель, где BionicPRO не переносит персональные и медицинские данные между странами.
* Backend получает только проверенный пользовательский контекст и не работает напрямую с внешними IdP.

# Разработка сервиса отчётов

Для схемы `BionicPRO_C4_model_airflow.drawio.xml` добавлена архитектура отчётности на базе ETL-процесса и OLAP-витрины.
Для удобства чтения из схемы убраны лишние компоненты и связи

## Что изменилось:

* Apache Airflow как оркестратор ETL-процесса: он по расписанию запускает сбор и подготовку данных для отчётов.
* CRM-система / CRM DB как источник клиентских данных: ФИО, email, пользователь, протез, модель, серийный номер.
* Telemetry DB как источник данных с протезов: события, время отклика, заряд батареи, качество сигнала и другие метрики.
* OLAP DB / ClickHouse как отдельное хранилище для отчётной витрины.
* Витрина `user_reports` в OLAP: заранее подготовленная таблица, где данные CRM и телеметрии уже объединены и агрегированы по пользователю и протезу.
* Сервис отчетов как backend-сервис для выдачи отчётов пользователю.

# Запуск проекта

```shell
make compose-up
```

Будут запущены все необходимые сервисы для проекта, включая добавленный сервис отчетов.

После логина пользователь может просмотреть свои отчеты. Отчеты для своих устройств доступны только своим пользователям.

## Команда для наполнения отчетов

```shell
make etl
```

Команда создаёт в ClickHouse таблицу-витрину `user_reports`, если её ещё нет, запускает ETL-шаг: берёт данные из CRM и telemetry DB, 
объединяет и агрегирует их, затем записывает готовые отчёты в ClickHouse в таблицу `user_reports`.
